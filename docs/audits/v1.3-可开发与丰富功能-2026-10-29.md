# v1.3 后续可开发与丰富功能

日期：2026-10-29。以下是可选产品/工程扩展，**不计作当前版本缺陷或安全漏洞**。修复项与扩展项的边界见[完整审计报告](v1.3-完整代码与可用性安全审计-2026-10-29.md)。本轮没有实施、安装或发布这些功能。

| 扩展 | 用户价值 | 建议边界与实现方向 |
| --- | --- | --- |
| 历史搜索、归档、导出与按需保留 | 历史多于当前最近 100 次后仍可方便检索，控制磁盘增长 | 当前“最近 100 次”已有明确说明，缺少扩展不算 bug。删除/保留策略应可预览，不能默认自动删除用户数据 |
| 可重现的规则快照与扫描对比 | 比较两次扫描新增/消失域名，重新导出时选择当时或当前规则 | 明确快照空间成本和许可证归属；先做必要的版本引用，再考虑完整历史快照 |
| Provider 与客户端接入助手 | 减少复制规则到 Mihomo/sing-box 的步骤 | 先补现有导出说明；一键编辑客户端、重载、修改代理是独立外部影响功能，不应由普通下载按钮暗中执行 |
| 第三规则来源适配器 | 扩展数据覆盖和来源选择 | 先确定真实来源需求，再将下载、解析、许可、缓存与归属抽成小接口；不要先构造空插件框架 |
| 机器可读 API 契约与贡献指南 | 人和 AI 能更快查清数据类型、错误码和执行入口 | 增加 OpenAPI/契约样例、目录地图、跨平台原生命令和隔离测试说明；保留 Host/Origin/Token 与私网保护 |
| 更多采集覆盖模式 | 有条件支持新标签页、独立 Worker、更多交互覆盖 | 当前 README 已公开覆盖限制，缺少这些不是 v1.3 bug。增加时要处理权限、取消、来源归属和资源配额，不能把失败/未操作流程声称为完整覆盖 |
| 开发质量与安全维护工具 | 及早发现依赖告警、状态失效和格式问题 | 可增加格式化、契约检查、跨浏览器回归与依赖更新 PR。A01 已发现的旧运行时问题仍属于修复，工具体系的丰富属于后续维护能力 |
| 更广平台发行与签名 | 降低 Windows 首次运行阻力，提供明确 Linux/ARM/macOS 成品支持 | 签名、安装器、自动更新、更多平台打包分别评估；需要真实目标环境验收，不能以交叉编译代替实测 |
| 远程/多人服务形态 | 支持多人访问或受控远程部署 | 这会改变当前本地单用户工具的安全模型，需认证授权、任务归属、隔离、配额、审计与部署设计；不能只开放监听地址 |
| 更简洁的初学者帮助 | 让不熟悉规则格式的人按任务完成操作 | 优先在现有字段增加一句帮助或一个最小示例；必要时渐进展开，避免多加首页卡片、长段说明和多级页面 |

建议先修复审计确认的问题，再按真实使用需求选择扩展。缺少实体手机、Safari 或新系统的证据，应通过补测解决，不能直接等同于需要开发新功能。
