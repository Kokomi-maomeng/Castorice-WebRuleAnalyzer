## 地址与网络行为

格式合法、域名存在、网络可连、页面完成和业务可用是不同结论。输入名称相近的有效域名不会自动变为另一服务；Google Gemini 的入口提示需要用户明确选择。

system 使用系统答案；auto 只回退已知 Fake-IP，保持混合受限答案拒绝；secure 明确使用所选 HTTPS DNS 替代系统解析。Cloudflare、Google 为内置固定端点，正常验证 TLS，拒绝 HTTP 重定向。一个地址族的普通故障可采用另一族的可用地址，但实际返回的受限地址仍会阻止连接。

本机上游仅支持无认证的 HTTP/SOCKS5 回环 IP 和端口。上游地址与目标策略分开；目标在每次连接前校验，CONNECT/SOCKS 请求使用通过校验的字面 IP。没有新增目标私网开关，不会修改操作系统或代理客户端配置。

真实检查中，Facebook 在独立安全 DNS 与本机代理路径下取得主文档 HTTP 200 并完成采集；错误域名的 NXDOMAIN 能正确显示。目标站点的重定向、TLS、加载时限与业务限制仍按实际结果记录。主文档已返回 200 而子资源加载超时的情况，会同时保留状态码、标题和超时诊断。

## 发布与边界

发布附件只包含应用、公开文档、许可证和校验值。部署记录、凭据、用户数据、日志、浏览器 Profile、测试数据库和个人路径位于本地排除目录，不作为发布输入。隐私检查只输出命中文件与规则身份，仍需结合 diff 和附件清单审阅。

CI 状态以关联 PR / Actions 为准；发布附件从 GitHub 再次下载校验。Windows 10、缺失 WebView2 的全新环境、macOS、Safari、Firefox及所有网站业务/代理客户端组合没有在本轮全部实机验证。普通 HTTP 200 或 TCP 成功不代表登录、地区限制及业务功能完整可用。
