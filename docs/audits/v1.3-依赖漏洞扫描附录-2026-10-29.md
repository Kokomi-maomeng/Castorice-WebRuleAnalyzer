# v1.3 依赖漏洞扫描附录

扫描日期：2026-10-29。源码/成品基线为 `299395bee80394ae35e0743777fecf85c5e0cf1d`，正式 EXE 编译器为 Go 1.26.2。主报告的 [A01](v1.3-完整代码与可用性安全审计-2026-10-29.md) 将旧安全基线计为一个优先修复事项，不把下面各条都当作已利用成功的独立应用漏洞。

扫描使用本轮获取的 `golang.org/x/vuln v1.9.0`。源码符号扫描报告 21 条标准库问题，另提示 5 条导入包/11 条依赖模块问题未显示调用对应漏洞符号。去掉调试/符号信息的发行 EXE 进行二进制扫描时报告 37 条；模块存在、包存在、符号可达与运行时可利用是不同证据层次。

本轮没有对全部报告分别构造攻击。程序默认回环、HTTP 服务配置、TLS 使用方式与调用输入均会影响可利用性。正式包需要随工具链修复重新构建，仅改依赖声明不会修复旧 EXE。

## 3. npm 与复核命令

`npm audit --json` 本轮返回 info/low/moderate/high/critical 均为 0，依赖总计 222。它不覆盖 Go 标准库、浏览器 Runtime、容器基础镜像及应用自己的状态/业务缺陷。

```text
go run golang.org/x/vuln/cmd/govulncheck@latest ./...
go run golang.org/x/vuln/cmd/govulncheck@latest -mode=binary <隔离验证的正式EXE路径>
npm audit --json
```

复核时记录工具版本、日期、源码提交和二进制哈希。`@latest` 与漏洞库都会变化，未来条目数可能不同。原始日志、机器可读逐项摘要在 `.runtime/audit-v1.3-20261029/`，本轮未升级产品依赖或发布修复包。
