# Castorice-WebRuleAnalyzer v1.1

Web分流规则分析器 · Windows x64 原生桌面便携版。

1. 解压整个运行包至可写文件夹，双击 `Castorice-WebRuleAnalyzer.exe`。无需命令行、Go、Node.js 或 Rust。
2. 独立软件窗口直接打开。界面需要已安装的 Microsoft Edge WebView2 Runtime；采集需要 Chrome、Edge 或 Chromium，可在设置选择路径。缺少 Runtime 时使用微软官方安装地址：https://developer.microsoft.com/microsoft-edge/webview2/
3. 输入网址，选择快速扫描、自动探索或辅助交互，点击开始分析。辅助交互使用另开的独立采集浏览器，在当前标签页手动操作。
4. 左侧只显示实际观察域名。点击“预览与导出规则”，核对格式和策略组，再点“保存到软件目录”。文件保存到软件旁 `exports/`；重名自动编号，不覆盖。
5. 如需合并，先在“规则库”初始化，再选择分类并预览来源。离线时已有缓存可用；没有缓存也能导出实际观察结果。
6. 点击主窗口右上角 × 退出。正在运行的扫描会取消，应用所属浏览器与本地服务一起关闭；不会结束用户自己打开的 Chrome/Edge。

`data/` 保存全部应用数据：SQLite 设置与历史、规则缓存、桌面 WebView2 缓存、日志、临时文件与独立扫描 Profile。`exports/` 保存导出文件。移动软件时携带整个文件夹。正常退出清理临时扫描 Profile 和 tmp，保留设置、历史及规则缓存。退出检查报告在 `data/logs/last-exit.json`，正常应为 `RemainingProcesses: 0`、`exit_code: 0`。

不要在压缩包内直接打开 EXE；不要放在没有写权限的 Program Files 等受限目录。目录不可写时会明确报错，不会静默写入用户 AppData。同一软件目录只能运行一个实例。v1.1 不会自动复制旧版 AppData 数据。

Clash YAML 的策略组需在客户端中存在；Provider 使用 classical 且不附策略组；sing-box JSON 是 Source Rule Set v3，不是完整客户端配置。

HTTP/3/QUIC 当前关闭。新标签页、独立 Worker 与未操作功能的请求可能没有覆盖；扫描结果不代表全应用完整覆盖。程序不自动登录、不绕过安全验证、不解密系统 HTTPS 流量。

应用自身生成的数据均定向至软件文件夹；Windows 自身的系统事件、预取及已安装 Runtime 的更新记录由操作系统管理。若异常退出，重新打开会恢复历史状态并清理应用拥有的残留会话。
